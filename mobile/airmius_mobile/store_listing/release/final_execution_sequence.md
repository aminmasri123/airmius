# Airmius Mobile Final Execution Sequence

Use this short sequence when the operator is ready to collect real release evidence.

For a compact command-only view, use:

- `store_listing/release/final_command_cheatsheet.md`

## 1. Run automated local evidence

The full pipeline checks local prerequisites automatically. You can also run the prerequisite check separately before starting:

```powershell
cd C:\xampp\htdocs\airmius\mobile\airmius_mobile
.\scripts\assert_local_release_prerequisites.ps1
```

Run the evidence pipeline:

```powershell
cd C:\xampp\htdocs\airmius\mobile\airmius_mobile
.\scripts\run_full_release_evidence_pipeline.ps1 -ApiBaseUrl "https://app.airmius.com"
```

If Flutter is not in `PATH`, pass the absolute Windows Flutter path:

```powershell
.\scripts\run_full_release_evidence_pipeline.ps1 -ApiBaseUrl "https://app.airmius.com" -FlutterCommand "C:\flutter\bin\flutter.bat"
```

This generates local Android/analyze evidence, syncs eligible manifest gates, exports a report and packages the first evidence bundle.

The prerequisite step writes:

- `release_evidence/local-release-prerequisites.log`

The pipeline syncs this log into the manifest immediately before later build/analyze steps run.

After the first bundle is packaged, the pipeline syncs the bundle evidence into the manifest, refreshes the evidence report and next-steps report, then packages the bundle again so the handoff ZIP reflects the latest manifest state.

## 2. Complete manual evidence gates

Prepare the manual evidence folder structure if it does not exist yet:

```powershell
.\scripts\new_manual_release_evidence_pack.ps1
```

```powershell
.\scripts\show_manual_evidence_gates.ps1
```

Complete every open manual gate listed in:

- `store_listing/release/manual_evidence_gates.md`

Update completed gates with:

```powershell
.\scripts\update_release_evidence_gate.ps1 -GateId "real_api_qa" -Status "passed" -Note "Evidence attached in release package."
```

After screenshots, logs and sign-offs are attached, verify the local manual evidence pack:

```powershell
.\scripts\assert_manual_release_evidence_pack.ps1
```

## 3. Verify manifest and status

```powershell
.\scripts\assert_release_manifest_integrity.ps1
.\scripts\show_release_evidence_status.ps1
.\scripts\show_next_release_steps.ps1
.\scripts\export_next_release_steps_report.ps1
```

The integrity and status commands must be clean before final Go/No-Go. The status command prints the current evidence progress percentage and remaining evidence percentage from the manifest gates. The next-steps command lists the next open gates with the command, runbook or evidence action to complete. The exporter writes `store_listing/release/generated_next_release_steps.md`.

## 4. Run final Go/No-Go

```powershell
.\scripts\run_full_release_evidence_pipeline.ps1 -ApiBaseUrl "https://app.airmius.com" -RunGoNoGo
```

With an absolute Flutter path:

```powershell
.\scripts\run_full_release_evidence_pipeline.ps1 -ApiBaseUrl "https://app.airmius.com" -FlutterCommand "C:\flutter\bin\flutter.bat" -RunGoNoGo
```

This validates the manual evidence pack, verifies manual gates, validates the manifest, runs Go/No-Go, marks the Go/No-Go gate passed after success, refreshes the final report and packages the final evidence bundle.

The manual evidence pack check writes and is synced into the manifest before Go/No-Go:

- `release_evidence/manual-evidence-pack.log`

At the end, the pipeline prints the next open release steps from:

- `scripts/show_next_release_steps.ps1`

## 5. Final output

Expected final package:

- `store_listing/release/airmius_release_evidence_bundle.zip`

Expected final report:

- generated by `scripts/export_release_evidence_report.ps1`

Expected next-steps report:

- generated by `scripts/export_next_release_steps_report.ps1`

## Hard rule

Do not submit to Play Store or App Store until final Go/No-Go passes and the final evidence bundle is produced.
